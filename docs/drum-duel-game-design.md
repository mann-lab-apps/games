# Drum Duel 게임 기획

## 한 줄 설명

컴퓨터가 4틱짜리 리듬을 들려주면, 플레이어가 다음 4틱 동안 같은 박자를 하이햇 입력으로 재연하는 리듬 기억 게임.

## 핵심 재미

플레이어가 느껴야 하는 감정은 "들었다", "맞췄다", "조금 더 빨라도 될 것 같은데?"이다.

이 게임은 드럼 소리를 구분하는 게임이 아니다. 음색 판별은 빼고, 짧은 리듬 기억과 박자 입력의 손맛에 집중한다.

## 기본 루프

1. 카운트인 또는 시각 펄스로 템포를 알려준다.
2. 컴퓨터가 4틱짜리 리듬을 재생한다.
3. 바로 다음 4틱이 플레이어 입력 구간이 된다.
4. 플레이어가 같은 박에 화면을 탭한다.
5. 박자가 맞으면 스테이지를 클리어한다.
6. 다음 스테이지는 더 빠르거나 더 복잡한 패턴으로 시작한다.
7. 틀리면 런이 종료된다.
8. 최고 도달 스테이지가 Best Score로 저장된다.

## MVP 규칙

입력은 하나만 둔다.

- 플레이어는 화면 전체 또는 큰 드럼 패드를 탭한다.
- 플레이어 입력은 모두 하이햇 느낌의 짧은 소리로 재생한다.
- 컴퓨터 재생도 첫 버전에서는 하이햇 하나만 사용해도 된다.
- 스네어와 하이햇을 섞는 것은 나중에 연출용으로 추가할 수 있지만, 정답 조건은 박자만 본다.

첫 프로토타입은 "어떤 소리였나"보다 "언제 쳤나"를 맞추는 게임으로 고정한다.

## 타이밍 모델

각 스테이지는 4틱으로 구성된다.

예시:

```txt
틱:       1   2   3   4
컴퓨터:   x       x x
플레이어: x       x x
```

첫 구현 추천:

- 그리드: 4개의 4분음표 틱
- 패턴 값: 각 틱마다 입력 있음/없음
- 판정 창: 시작값은 +/- 140ms 근처
- 추가 입력: 실패
- 필요한 입력 누락: 플레이어 입력 구간 종료 후 실패
- 너무 이르거나 늦은 입력: 실패

판정 창은 실제 기기에서 손맛을 보고 조정한다.

## 난이도 설계

난이도는 두 축으로 올린다.

템포:

- 1스테이지: 80 BPM
- 5스테이지: 100 BPM
- 10스테이지: 120 BPM
- 20스테이지: 150 BPM

패턴 복잡도:

- 초반은 1-2개 입력
- 이후 3개 입력 추가
- 첫 박이 쉬는 패턴 추가
- 붙어 있는 박 추가
- 이후 후보로 8분음표 subdivision 추가

MVP에서는 8분음표를 바로 넣지 않는다. 4틱만으로 재미가 있는지 먼저 확인한다.

## 패턴 생성

MVP는 랜덤 생성보다 curated pattern list로 시작한다.

초기 패턴 후보:

```txt
x . . .
x . x .
x . . x
x x . .
. x . x
x . x x
x x . x
. x x .
```

규칙:

- 전부 쉼표인 패턴은 제외한다.
- 초반에는 모든 틱을 치는 패턴을 피한다.
- 같은 패턴도 BPM이 오르면 다시 등장할 수 있다.
- 난이도는 랜덤보다 "읽히는 상승감"이 중요하다.

## 피드백

컴퓨터 재생:

- 매 틱마다 시각 펄스가 있다.
- 입력이 있는 틱에서는 컴퓨터 패드가 더 강하게 반응한다.
- 소리는 짧고 건조하게 둔다.

플레이어 입력:

- 탭 즉시 하이햇 소리와 패드 플래시가 나온다.
- 정답은 짧고 선명하게 성공 피드백을 준다.
- 틀린 입력은 붉은 타이밍 마크 또는 흔들림으로 표시한다.
- 클리어 후 다음 스테이지로 빠르게 넘어간다.

런 종료:

- 도달 스테이지
- 최고 기록
- 다시하기 버튼

## 화면 구성

MVP 화면:

- 상단: 현재 스테이지, 최고 기록
- 중앙: 4틱 마커
- 하단 또는 전체 화면: 큰 탭 패드
- 플레이 중 설명 문구는 최소화

비주얼은 Mann Lab Games의 손그림 스케치 방향을 따르되, 리듬 마커의 판독성이 가장 중요하다.

참조:

- `docs/visual-direction.md`

## MVP 범위

첫 구현에 포함:

- 4틱 컴퓨터 재생
- 4틱 플레이어 응답
- 단일 입력
- BPM 상승
- curated pattern list
- 타이밍 판정
- 스테이지 클리어
- 런 실패
- 로컬 최고 기록 저장
- 다시하기

첫 구현에서 제외:

- 필수 음색 구분
- 긴 곡 구조
- 배경 음악 트랙
- 온라인 랭킹
- 광고
- 스킨
- 튜토리얼 화면

## 열어둘 질문

- 컴퓨터 재생 직후 바로 입력을 받을까, 아니면 1틱 쉬고 받을까?
- 실패는 즉시 런 종료가 좋을까, 생명 1-3개가 좋을까?
- 컴퓨터 소리는 나중에 스네어/하이햇으로 섞되 정답은 박자만 볼까?
- 화면 전체 탭이 좋을까, 눈에 보이는 드럼 패드가 좋을까?
