# 고전 캐주얼 + 하나 비틀기 전략

## 배경

마케팅 노출 없이 App Store Connect의 자연 유입만 관측되는 상황에서 `2048 Crash`만 상대적으로 의미 있는 첫 다운로드 신호를 만들었다.

2026-08-21 스크린샷 기준:

| 게임 | 노출 수 | 제품 페이지 조회 수 | 최초 다운로드 수 | 전환율 |
| --- | ---: | ---: | ---: | ---: |
| `2048 Crash` | 110 | 3 | 5 | 5.26% |
| `10000 by MannLab` | 115 | 9 | 1 | 1.16% |
| `Dopamine Swap` | 139 | 2 | 0 | - |
| `Wind Gull` | 6 | - | - | - |

표본은 아직 작다. 다만 같은 조건에서 `2048 Crash`만 다운로드가 발생했다는 점은 다음 가설을 세울 만큼의 신호로 본다.

## 핵심 가설

`이미 아는 고전 규칙 + 첫 화면에서 이해되는 한 가지 반전`이 작은 팀의 무마케팅 출시에서 유리하다.

이 전략의 장점:

- 유저가 앱 이름과 아이콘만 보고도 기본 플레이를 추측할 수 있다.
- App Store 검색에서 이미 존재하는 기능/장르 키워드의 도움을 받을 수 있다.
- 튜토리얼, 카피, 스크린샷의 설명 비용이 낮다.
- 작은 비틀기 하나만 잘 설계해도 "알 것 같은데 새롭다"는 클릭 이유가 생긴다.

이 전략의 위험:

- 고전 게임을 그대로 복제하면 App Review에서 copycat/spam 리스크가 생긴다.
- 타사 상표, 보호받는 이름, 유명 앱 이름을 메타데이터에 넣으면 심사/법적 리스크가 생긴다.
- 반전이 너무 약하면 스킨만 바꾼 앱처럼 보이고, 너무 많으면 고전 규칙의 장점을 잃는다.

## 전략 원칙

1. 한 줄 설명은 `X인데 Y가 있다`로 끝나야 한다.
   - 좋은 예: `2048인데 움직이지 않는 목표 블록을 깨야 한다.`
   - 나쁜 예: `숫자 퍼즐에 여러 특수 룰과 레벨업, 아이템, 콤보가 있다.`
2. 비틀기는 MVP에서 하나만 둔다.
   - 새 입력 방식 1개, 새 실패 조건 1개, 새 목표 1개 중 하나를 고른다.
   - 스킨, 재화, 레벨맵, 광고 보상은 후순위다.
3. 앱 이름은 검색 의도와 반전을 같이 보여준다.
   - 구조 후보: `<classic keyword> <twist word>`
   - 예: `2048 Crash`, `Snake Merge`, `Minesweeper Drift`
4. 스크린샷 1장은 "고전 규칙", 1장은 "비틀기 순간", 1장은 "실패/기록"을 보여준다.
5. 각 앱은 독립 게임처럼 보여야 한다.
   - 같은 템플릿 UI를 쓰더라도 보드, 피드백, 점수명, 실패 조건, 아트 톤은 게임별로 달라야 한다.
6. 상표/저작권이 있는 표현은 피한다.
   - 유명 브랜드명, 경쟁 앱 이름, 보호받는 캐릭터/그래픽/사운드는 쓰지 않는다.
   - `Tetris`, `Wordle`, `Arkanoid`처럼 강한 상표 자산이 있는 이름은 제목/키워드/스크린샷 텍스트에서 피한다.

## App Store 근거

Apple의 App Store 검색 설명은 검색 결과가 앱 제목, 부제목, 키워드, 기본 카테고리의 텍스트 관련성과 다운로드, 평점, 리뷰 같은 사용자 행동 신호를 함께 본다고 설명한다. 따라서 이름만 보아도 장르와 기능이 선명한 게임은 초기 자연 유입에서 유리할 수 있다.

동시에 App Review Guidelines는 단순 카피앱, 사소한 이름/UI 변경, 구분되지 않는 변형 앱, 보호받는 상표/저작권 사용을 제한한다. 이 전략은 "고전 규칙의 문법을 빌리되, 독립적인 목표와 의사결정을 만든다"는 선을 지켜야 한다.

참조:

- Apple Developer, App Store search: https://developer.apple.com/app-store/search/
- Apple Developer, Discovery on the App Store: https://developer.apple.com/app-store/discoverability/
- Apple Developer, App Review Guidelines 4.1, 4.3, 5.2: https://developer.apple.com/app-store/review/guidelines/

## 후보 선정 점수표

새 후보는 5점 만점으로 빠르게 평가한다.

| 기준 | 질문 |
| --- | --- |
| 인지 자산 | 이름이나 스크린샷만 보고 기본 규칙을 떠올릴 수 있는가? |
| 검색 의도 | 유저가 App Store에서 실제로 찾을 법한 장르/기능 키워드가 있는가? |
| 반전 선명도 | 한 문장으로 차이를 설명할 수 있는가? |
| 독립성 | 원본과 다른 목표, 실패 조건, 의사결정이 있는가? |
| 구현 크기 | 1-2주 안에 MVP를 만들 수 있는가? |
| 반복성 | 최고 기록, 랜덤 시드, 난이도 상승으로 다시 할 이유가 있는가? |
| 심사 안전성 | 상표, 그래픽, 사운드, 유명 앱 메타데이터를 피할 수 있는가? |

우선순위는 `인지 자산`, `반전 선명도`, `심사 안전성`, `구현 크기`를 가장 높게 둔다.

## 참조할 모바일 고전 캐주얼 게임

| 고전 규칙군 | 모바일에서 강한 이유 | 비틀기 후보 | 주의점 |
| --- | --- | --- | --- |
| 2048 / 숫자 합치기 | 스와이프 한 번으로 조작되고 숫자 성장 목표가 즉시 보인다. | 목표 블록 깨기, 보드에 고정 장애물, 숫자별 중력, 제한 이동 수 | `2048` 표기는 널리 쓰이지만 원작과 구분되는 룰/비주얼을 유지한다. |
| Minesweeper / 지뢰찾기 | 짧은 추론, 실패 긴장, 작은 화면 격자와 잘 맞는다. | 지뢰가 매 턴 이동, 힌트가 밀림, 안전 구역을 연결해야 함 | Windows식 그래픽/아이콘을 베끼지 않는다. |
| Snake / 뱀 게임 | 조작이 단순하고 실시간 긴장이 강하다. | 몸통 숫자 merge, 꼬리 자르기 선택, 벽이 매 턴 변형 | 유명 Nokia/레트로 표현을 직접 복제하지 않는다. |
| Solitaire / 카드 정렬 | 모바일 장기 체류가 검증된 혼자 하는 퍼즐이다. | 제한된 undo, 카드 열 잠금, 1분 러시, 덱이 오염되는 룰 | 실제 카드 그래픽은 직접 제작하고, 카지노/도박 인상을 피한다. |
| Sudoku / 숫자 논리 | 검색 의도와 반복 플레이가 강하다. | 숫자 입력 대신 swap, 매 턴 한 줄 회전, 작은 4x4/6x6 러시 | 난이도 생성/검증 로직이 필요하다. |
| Word puzzle / 단어 추론 | 일일 도전과 공유성에 강하다. | 글자 위치가 회전, 오답이 보드 장애물이 됨, 제한된 swap | `Wordle` 등 특정 상표/제품명 사용을 피한다. |
| Sliding puzzle / 15 퍼즐 | 룰 설명이 거의 필요 없고 작은 화면에서 명확하다. | 퍼즐 안에 열쇠/문/몬스터, 목표 타일 탈출, 숫자 합치기 | 사진 슬라이드 퍼즐만으로는 차별성이 약하다. |
| Sokoban / 박스 밀기 | 한 손 조작, 명확한 실패, 스테이지 제작이 쉽다. | 박스가 합쳐짐, 박스가 깨짐, 밀 때마다 방이 줄어듦 | 레벨 수보다 생성/변주 규칙을 먼저 만든다. |
| Brick breaker / 벽돌깨기 | 타격감과 숫자 감소 피드백이 강하다. | 벽돌 숫자 merge, 공이 자원, 벽돌이 퍼즐 보드처럼 이동 | `Arkanoid` 등 상표명과 유사한 표현을 피한다. |
| Bubble shooter / 버블 맞추기 | 색 매칭과 포물선 조준이 직관적이다. | 색 대신 숫자/방향, 버블이 중력으로 합쳐짐, 한 발마다 판 회전 | 에셋과 UI가 흔해 보이면 spam 리스크가 커진다. |
| Match-3 / 3매칭 | 가장 넓은 캐주얼 문법 중 하나다. | 한 번에 한 칸만 swap, 매치가 보드를 파괴, 목표 타일 이동 | 경쟁이 매우 높아 이름/스크린샷 차별화가 필수다. |
| Flappy / 탭 비행 | 한 손, 즉시 실패, 기록 경쟁이 강하다. | 바람 읽기, 에너지 제한, 장애물 대신 경로 퍼즐 | 유명 캐릭터/파이프 구성의 직접 복제를 피한다. |
| Memory / 카드 뒤집기 | 짧은 세션과 누구나 아는 룰이 장점이다. | 카드 위치가 바뀜, 틀리면 카드가 합쳐짐, 제한된 시야 | 단순 메모리 게임만으로는 차별성이 약하다. |
| Dots / 선 연결 | 터치 드래그가 자연스럽고 보기 쉽다. | 선이 교차하면 깨짐, 숫자 목표 합, 제한된 잉크 | 너무 추상적이면 검색 키워드가 약해질 수 있다. |
| Nonogram / 픽셀 로직 | 퍼즐 유저에게 검색 의도가 뚜렷하다. | 실시간 붕괴, 작은 러시판, 색이 섞이는 룰 | 퍼즐 생성/검증 비용이 있다. |

## 우선 실험 후보

### 1. 2048 Blink

한 줄 설명: 2048인데 매 턴 Gray Cross가 지나가며 그 위의 숫자만 가려진다.

좋은 점:

- `2048 Crash`의 자연 유입 신호를 같은 규칙군에서 한 번 더 검증할 수 있다.
- 비틀기가 "회색 십자 라인이 숫자를 흐린다"로 선명하고 스크린샷에서 즉시 보인다.
- 기존 2048 보드/입력 경험을 재사용할 수 있어 MVP 구현이 빠르다.

MVP:

- 4 x 4 보드
- 일반 2048 이동/합치기/스폰/게임 오버 규칙
- 매 턴 한 행과 한 열을 예측 가능한 Gray Cross로 처리
- 회색 타일은 숫자만 숨기고 점유 여부는 유지
- 최고 타일과 점수 저장

### 2. Minesweeper Drift

한 줄 설명: 지뢰찾기인데 매 턴 힌트 줄이 한 칸씩 밀린다.

좋은 점:

- `Minesweeper` 계열의 인지 자산이 강하다.
- 숫자 힌트가 "움직인다"는 반전이 스크린샷으로 보인다.
- 작은 보드 MVP로 시작할 수 있다.

MVP:

- 8 x 8 보드
- 탭으로 칸 열기, 길게 눌러 깃발
- 플레이어 입력 후 한 행 또는 한 열의 힌트 오프셋이 바뀜
- 지뢰 위치는 고정하되 표시 힌트만 drift
- 목표는 모든 안전 칸 열기

### 3. Snake Merge

한 줄 설명: 뱀 게임인데 먹은 숫자가 몸통에서 합쳐지고, 너무 커진 몸통이 길을 막는다.

좋은 점:

- 실시간 액션과 숫자 merge가 합쳐져 `2048 Crash`와 포트폴리오 연결성이 있다.
- 아이콘/스크린샷에서 차이를 보여주기 쉽다.
- 최고 기록형으로 단순하다.

MVP:

- 격자 기반 자동 이동
- 좌우 스와이프로 방향 전환
- 같은 숫자 몸통이 붙으면 합쳐짐
- 벽/자기 몸통 충돌 시 종료
- 점수는 만든 최고 숫자와 생존 시간

### 4. Slide Dungeon

한 줄 설명: 15퍼즐처럼 방을 밀어서 열쇠를 출구까지 보내는 미니 던전 퍼즐.

좋은 점:

- 고전 슬라이딩 퍼즐 문법에 캐릭터 목표가 붙어 차별화가 쉽다.
- 상표 리스크가 낮다.
- 레벨 기반으로 App Store 스크린샷이 잘 나온다.

MVP:

- 4 x 4 슬라이딩 보드
- 빈 칸 하나
- 열쇠, 문, 위험 타일
- 제한 이동 수 안에 열쇠를 문으로 이동

## 실험 운영

1. 후보별로 1페이지 기획서를 작성한다.
2. 1-2주 안에 플레이 가능한 MVP를 만든다.
3. 광고 없이 App Store 또는 TestFlight/웹에서 기본 지표를 본다.
4. 최소 관측 지표:
   - 노출 수
   - 제품 페이지 조회 수
   - 최초 다운로드 수
   - 전환율
   - 첫 실행 수
   - 첫 런 완료율
   - 재시작률
5. 표본이 작을 때는 승패를 단정하지 않고, 같은 조건에서 상대 비교만 한다.

초기 판단 기준:

- 다운로드가 0이면 이름, 아이콘, 첫 스크린샷을 먼저 고친다.
- 제품 페이지 조회는 있는데 다운로드가 낮으면 스크린샷/설명/아이콘의 약속이 약한 것이다.
- 다운로드는 있는데 첫 런 완료율이 낮으면 튜토리얼 또는 첫 30초 룰이 문제다.
- 첫 런 완료와 재시작이 살아 있으면 해당 게임만 업데이트 후보로 올린다.
